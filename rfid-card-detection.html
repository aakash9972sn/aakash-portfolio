01 / THE APPROACH

A small system.
A complete signal path.

The engineering task is to turn a contactless card presentation into an identifier that a microcontroller can interpret—and a response a person can understand.

This project focuses on the complete detection path: energize a compatible passive card, read its UID, compare it with a registered value and show the result. A Serial Monitor exposes the data for debugging; two LEDs and an active buzzer provide immediate feedback.

01

Detect a compatible card

Use a 13.56 MHz, ISO/IEC 14443 Type A card or tag supported by the reader. A 125 kHz card belongs to a different RFID family.

02

Read the whole identifier

Compare the UID length and every byte. Card identifiers may be 4, 7 or 10 bytes; the example must not assume that all cards have four.

03

Make the result visible

A registered UID selects the green LED. An unregistered compatible card selects the red LED. A short beep acknowledges a successful read.

Scope of this build

This is a foundational identification design. It does not store attendance, measure time on site or provide cryptographically authenticated door access. Those are separate engineering requirements.

02 / RF PRINCIPLE

A card powered
by the reader.

The reader creates an alternating magnetic field at 13.56 MHz. A nearby passive card couples to that field through its antenna coil, obtaining the energy needed to power its chip. It does not need a battery for normal operation.

Faraday’s law of inductione=−NdΦBdt

The card responds through load modulation: changes in the load on its antenna produce changes the reader can detect. At the short distances used here, the exchange takes place through near-field magnetic coupling.

The practical read range depends on both antennas, card orientation, nearby materials and supply quality. The report cites the MFRC522’s antenna-dependent range of up to approximately 50 mm; that is a datasheet condition, not a measured result for this setup.

RF / ENGINEERING NOTES

Frequency is fixed.
Coupling is not.

At 13.56 MHz, the free-space wavelength is approximately 22.12 m. This does not mean a small RC522 reads a card from that distance: this design uses short-range magnetic coupling between nearby coils.

Free-space wavelengthλ=cf=3×10813.56×106≈22.12 m

Antenna tuning, orientation, nearby metal and supply noise affect whether the card receives enough energy and the reader can recover its response. For an ideal LC model, the resonance is:

Ideal LC resonancef0=12πLC

These calculations explain the design principles. Actual antenna matching and dependable read distance need measurements on the chosen reader and card.

05 / FIRMWARE

Read. Compare.
Respond. Repeat.

  1. InitializeStart USB serial at 9600 baud, initialize SPI and the reader, and configure the output pins.
  2. Wait for a cardUse the library’s new-card check and card-selection call before accessing UID data.
  3. Print the identifierDisplay each UID byte in hexadecimal, including leading zeroes, for repeatable registration.
  4. Compare the UIDReject a length mismatch, then compare every byte against the configured credential.
  5. Signal the resultSelect the green or red LED and pulse the buzzer. The sample keeps feedback visible for about one second.
  6. End the exchangeHalt the selected card and stop the crypto session before returning to polling.

#include <SPI.h>
#include <MFRC522.h>

#define SS_PIN 10
#define RST_PIN 9
#define GREEN_LED 6
#define RED_LED 7
#define BUZZER 8

MFRC522 rfid(SS_PIN, RST_PIN);
const byte registeredUID[] = {0x12, 0x34, 0x56, 0x78}; // replace with your card's UID

bool isRegisteredCard() {
  if (rfid.uid.size != sizeof(registeredUID)) return false;
  for (byte i = 0; i < sizeof(registeredUID); i++)
    if (rfid.uid.uidByte[i] != registeredUID[i]) return false;
  return true;
}

void setup() {
  Serial.begin(9600);
  SPI.begin();
  rfid.PCD_Init();
  pinMode(GREEN_LED, OUTPUT); pinMode(RED_LED, OUTPUT); pinMode(BUZZER, OUTPUT);
  Serial.println("Place an RFID card near the reader");
}

void loop() {
  if (!rfid.PICC_IsNewCardPresent() || !rfid.PICC_ReadCardSerial()) return;
  Serial.print("UID:");
  for (byte i = 0; i < rfid.uid.size; i++) {
    Serial.print(rfid.uid.uidByte[i] < 0x10 ? " 0" : " ");
    Serial.print(rfid.uid.uidByte[i], HEX);
  }
  bool ok = isRegisteredCard();
  Serial.println(ok ? "  REGISTERED" : "  UNREGISTERED");
  digitalWrite(ok ? GREEN_LED : RED_LED, HIGH);
  digitalWrite(BUZZER, HIGH); delay(150); digitalWrite(BUZZER, LOW);
  delay(850);
  digitalWrite(GREEN_LED, LOW); digitalWrite(RED_LED, LOW);
  rfid.PICC_HaltA();
  rfid.PCD_StopCrypto1();
}

Registration and repeat testing

Install the MFRC522 library, select the UNO board and serial port, and upload the sketch. Read a card’s UID from the Serial Monitor, replace the placeholder registeredUID byte array, and upload again. Remove the card from the field before presenting it for another test.

A deliberate tradeoff in the reference sketch

The feedback delay makes the result easy to observe on a bench, but blocks polling while it runs. A later version could use a non-blocking state machine. The one-second indication interval must not be reported as the reader’s RF detection latency.

Troubleshooting checklist
  • Reader not found: check 3.3 V supply, common ground, chip select, reset and SPI wiring.
  • No card response: confirm the tag family and move the card closer, with its antenna parallel to the reader.
  • Unstable reads: shorten jumpers, check solder joints and stabilize the supply.
  • Unexpected registration result: compare the full UID and its length, not only the first bytes.
  • No feedback: check LED polarity, series resistors, buzzer type and output pin assignments.

07 / ENGINEERING TAKEAWAYS

What this project
connects.

01

RF meets firmware

Electromagnetic induction and antenna coupling become concrete when a passive card produces a UID in the serial console.

02

Interfaces include electricity

A matching pin name is not enough. Supply voltage, logic thresholds, current limits and a shared reference are part of the interface.

03

Identifiers have limits

A UID match identifies a registered value. Some identifiers can be copied; UID-only checking is unsuitable for security-critical access control.

04

Detection is the first layer

An RTC, persistent event storage and a person-to-card model are needed before this can become a meaningful attendance system.

The next project builds on that last distinction: a card scan is an event; reliable presence information requires timestamps, session reconstruction and an explicit policy for incomplete data.
